# V1 首次使用体验讨论：扫描周期

日期：2026-10-25。
状态：本节规则已获用户确认；用户授权存档，尚未授权修改设计稿或编码。

## 已确认：扫描按钮

- 按钮名称由“扫描新录音”改为“扫描录音”。
- 一次点击启动一个完整周期：扫描本次录音，并完成本次录音的处理。
- 扫描期间显示“正在扫描…”，按钮禁用。
- 处理期间显示“正在转写 · 2/5”等本轮处理序号，按钮禁用。
- “正在转写”是按钮上的汇总状态，涵盖音频准备、转写、分段、保存；具体阶段在任务列表展示。
- 本轮所有录音处理完成或明确失败后，恢复“扫描录音”，允许再次点击。
- 没有新录音时直接结束周期，提示“没有新录音”。
- 单份失败继续处理其余录音；本轮结束后失败任务保留重试入口。
- 周期内新增文件留待下一轮扫描，本轮任务范围固定。
- 保存完成或明确失败才算该录音处理结束，不能在转写文本产生时提前解锁。

## 已确认：模型准备与扫描入口（2026-10-25补充）

## 已确认：退出中断与继续处理（2026-10-26补充）

用户确认方案合适，延续逐项存档讨论；未授权修改设计或编码。

- 点击继续后恢复原周期，复用已保存的处理阶段；不重新扫描，不重复处理已完成任务。
- 恢复指从已保存阶段继续，不承诺从音频中断的具体秒数恢复。
- 本轮未完成前不允许启动新扫描；全部处理结束后恢复“扫描录音”。

## 已确认：失败任务重试重新入队（2026-10-26补充）

用户明确要求多个重试任务可以重新加入队列，并确认以下方案；仅存档，未授权修改设计或编码。

- 点击失败任务的“重试”，将该任务加入队尾，统一按已有队列流程依次处理。
- 可以连续加入多个失败任务；队列处理期间仍允许加入其他失败任务重试。

- 队列处理期间禁止扫描；新增重试任务后，处理进度的总数同步更新。
- 队列全部完成或明确失败后，恢复“扫描录音”。
- 此规则取代讨论中未采纳的“单个重试期间禁用其他重试入口”建议。扫描发现的新文件范围仍固定，手动加入重试任务是明确允许的队列追加。
