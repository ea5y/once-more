日期：2026-10-17。授权：用户“会议结束，同意执行本地验证”。本次仅验证本地引擎，不接入产品、不改变界面。

- whisper.cpp v1.8.2，提交 `4979e04f5dcaccb36057e059bbaed8a2f5288315`，本地 Release 编译。CMake 4.4.4 安装在项目验证目录的独立环境。
- 模型：large-v3-turbo Q5_0，574,041,195 字节（574 MB / 547 MiB）。SHA256：`394221709cd5ad1f40c46e6031ca61bce88931e6e088c188294c6d5a55ffa7e2`（本地计算，未与远端校验值比对）。
- 来源：https://github.com/ggml-org/whisper.cpp 及 https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo-q5_0.bin 。
- 使用已授权录音的项目内副本 `.local/verification/user-recording.m4a`，解码成 16 kHz 单声道 16 位 WAV，24.576 秒。未改原录音，未上传音频。
- 精简 FFmpeg 不含 pcm_s16le 编码器，本次通过其 float PCM 输出与 Python 标准库生成验证用 WAV；这不是已完成的产品依赖方案。

## 发现的问题

1. 输出包含疑似字幕署名和重复句子。没有人工逐句校对，不能确定哪些是误识别，不能报告准确率或自动删除重复句。
2. 默认输出繁体中文；尚未确定简体显示方案。
3. 默认句段时间戳较粗，不能直接当作自然对话边界；逐词对齐、静音检测及对话合并尚未验收。
4. `-ojf` 完整 JSON 的原始字节无法严格按 UTF-8 解码；替换非法字节后可解析，段落文字没有替换字符。疑似 token 文本包含拆分字节，需后续核查；不可把容错解析当作正式修复。普通 JSON 输出尚未测试。
5. 尚无长录音、噪声、多说话人或不同设备样本。本次不构成发布验收。

## 结论与待确认下一步

- 用户确认第一条短样本除开头 YK 误识别外基本正确，重复句也正确；接受少量误识别，要求全部转写，不追加 VAD／噪声过滤验证。
- 用户提供并授权转写 `/Users/luwanzhong/Downloads/中山西路3288号 2.m4a`。源文件时长 240.020 秒，解码 WAV 240.064 秒，16 kHz 单声道；处理前后 SHA256 均为 `e2df225de1c857e0fafdebc4efeb6b76af9b462161cd9c347980fda09199443c`。
- 沿用同一模型、中文、4 线程、Metal、默认解码参数；无 VAD、无文字清洗。输入只在本机读取，未上传。
- 完整转写进程耗时 **29.04 秒**（不含音频预处理），最大 RSS **939,802,624 字节，约 896 MiB**，peak memory footprint 838,848,768 字节。约为音频时长的 0.121 倍，比此前 24 秒样本线性推算更快；仍不能作为数小时录音的性能保证。

### 同日续验：普通 JSON 与时间顺序

- 用户“继续”后，以同一模型、音频和参数再次运行，仅输出选项改为 `-oj`，输出 `whisper-standard.json`，日志 `whisper-standard.log`。
- 普通 JSON 严格 UTF-8 解码及 JSON 解析通过。5 段文字、时间与首轮相同；起止顺序有效，相邻段无重叠。末尾仍超出实际音频 4 ms。顺序正确不代表与实际语音对齐准确。
- 第二次进程耗时 6.67 秒，最大 RSS 862,011,392 字节（约 822 MiB）。与首次初始化环境不同，不能据此推断长录音速度；本次没有改变识别参数来提高速度。
- 完整 JSON 的非法 UTF-8 定位在 token 的 text 字段：单个 token 输出了未完整组成汉字的字节。CLI 源码直接输出 `whisper_token_to_str`；因此后续句段接口优先使用普通 JSON，逐词接口需单独解决字节组合及对齐问题。未改上游代码。
- 尚待人工确认开头署名是否真实存在、相同句子是否实际说了两次；不自动清洗，不覆盖原始结果。静音处理尚未验证。

本机可以运行该模型，保留为候选；普通 JSON 与四分钟样本验证通过。遵循用户要求全部转写，不追加噪声过滤。尚待确认四分钟样本文字质量及实际时间边界，再讨论产品接入、模型下载界面和打包；数小时录音性能尚未验收。后续工作需按用户会议及执行确认规则推进。
