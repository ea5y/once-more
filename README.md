最新更新：已成功提取的最新范围改用WAV文件回听，从片段0秒计时；调整范围后使用原录音，重新提取成功后切换新文件。文件缺失会提示并停止，恢复文件可重试。范围弹框仍试听原录音，提取关联仍未持久化。

运行 `npm run dev:v1`，或启动开发服务后打开 `http://127.0.0.1:1420/?v1`。
该入口使用三天、12段模拟对话；支持日期切换、片段选择、收藏筛选、收藏操作、撤销、模拟播放/暂停、全局全文搜索、片段内搜索、点击句子模拟播放、当前句高亮和正文跟随（手动浏览后可返回当前句），换日期保留当前详情与模拟播放进度。范围弹框支持模拟起止时间校验、取消及保存，正文及标题随范围预览、保存更新，扩大可恢复模拟原句；支持范围模拟试听/暂停、到终点停止及修改范围后归零，仍无真实声音。提取入口复用范围确认弹框，确认后约3秒显示模拟结果；海边片段奇数次提交失败、偶数次成功（用于验证重试），其他片段模拟成功。失败保留范围，跨日期及筛选继续处理；已提取后可调整范围，变更后标记需要重新提取，成功后恢复已提取；原录音缺失时禁止调整。“同一录音”展示全部关联片段及按最新范围提取的完成汇总，包含未收藏片段；全部关联片段按最新范围模拟提取完成后可进入移到废纸篓确认；确认只更新模拟来源状态，不操作真实文件。扫描和真实文件操作显示为未开放，不会调用真实文件或云端接口。原有入口保留用于后续迁移，不代表V1已验收功能。

## 开发环境

- Node.js 24.21.0（`.nvmrc`）
- Rust stable（本机已安装 1.98.1）
- macOS：Xcode Command Line Tools
- Windows：Microsoft C++ Build Tools、WebView2
- FFmpeg / FFprobe：通过 `sh scripts/build-audio-tools.sh` 从官方源码构建精简音频版本，随后随应用资源打包。本机 Mac ARM64 工具已构建。

当前使用 npm，提交 `package-lock.json` 固定依赖，无需额外安装 pnpm。

```sh
source ~/.nvm/nvm.sh
nvm use
source ~/.cargo/env
npm ci
sh scripts/build-audio-tools.sh
npm run desktop
```

仅预览界面：`npm run dev`。浏览器中的本地文件夹功能不可用；可点击左下角「查看设计示例」体验设计稿数据。

## 当前功能

- 按 Penpot Page 1「Once More · V15 · 紧凑详情」实现三栏主界面。
- 首次使用、空录音库、搜索无结果、扫描状态。
- 独立的设计示例模式：不伪造音频、不写入真实记忆库。
- 原生选择来源与输出文件夹、扫描音频；重复扫描保留已有记录 ID。
- 浏览真实录音、系统 WebView 播放、手动选择起止时间并留下 Memory。
- 时间轴、日期切换、顺序切换、标题与原文搜索、留下筛选。
- SQLite 保存录音索引、手动记忆、设置与收听次数。
- FFmpeg 提取接口：指定区间导出 24-bit PCM WAV，使用唯一文件名，不覆盖来源文件。
- 音频工具已随当前 Mac 开发包附带；后台波形生成与缓存接口已实现，波形界面接入待完成。

当前真实记忆日期取自文件修改时间，类型标为「手动留下」。自动转写、声音事件分析、推荐、真实波形、文件移动重定位、完整任务历史与取消尚未实现。

## 数据位置

当前阶段数据库位于系统应用数据目录，macOS 为 `~/Library/Application Support/app.oncemore.desktop/once-more.sqlite3`。
用户选择的输出目录目前用于 `clips/` 音频导出。

这与早期产品文档中“数据库也放 Output Folder”的设想尚有差异：下阶段需要确定库目录迁移及备份方案。只备份录音不能恢复「留下」和人工修改，请同时保留数据库目录。

## 目录

- `src/`：React 界面、播放控制、交互与前端测试
- `src-tauri/`：Tauri 桌面壳、Rust 文件与数据逻辑
- `public/icons/`：既有时段 SVG 设计素材
- `docs/PROGRESS.md`：续做入口、验证结果和待办
- 根目录四份 Markdown：原始产品与命名文档

## 产品边界

来源文件仅被读取。当前不提供删除原始录音功能。「留下」保存索引，独立音频需要另外提取。转写、云上传与 AI 推理均未启用。
